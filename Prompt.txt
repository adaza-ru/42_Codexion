🏗️ 1. Las Estructuras de Datos (Tu .h)

El núcleo de todo es evitar las variables globales y centralizar el estado. Necesitas dos estructuras principales.
El Árbitro Central (t_env)

Esta estructura la crearás una sola vez en tu main y se la pasarás por puntero a todos los hilos. Controla la mesa, los turnos y los recursos.

    Configuración: num_coders, time_to_burnout, time_to_compile, etc., y el tipo de scheduler (0 para FIFO, 1 para EDF).

    El Heap (Los Dongles): Un array de enteros int heap_dongles[250]. Un 0 significa libre, un 1 significa que un coder lo está usando.

    La Cola de Prioridad: Un array int queue[250] donde guardarás los IDs de los coders que están esperando para compilar, y un int queue_size para saber cuántos hay.

    Sincronización:

        pthread_mutex_t arbitrator_mutex; (El candado principal para poder mirar y modificar el Heap y la Cola).

        pthread_mutex_t write_mutex; (Para que los printf salgan limpios).

        pthread_cond_t cond_coders[250]; (Un array de variables de condición. ¡Una sala de espera privada para cada coder!).

El Programador (t_coder)

Crearás un array de estas estructuras (una por cada hilo) para mantener su estado individual.

    Identidad: int id; (de 0 a num_coders - 1).

    Estado vital: long long last_compile_start; (para saber cuándo va a morir) y int compiles_done;.

    Referencia: Un puntero t_env *env; para poder comunicarse con el Árbitro Central.

⚙️ 2. El Flujo de Ejecución: Cómo pedir los Dongles

Cuando tu hilo Coder quiere ponerse a compilar, llama a una función (ej. take_dongles(t_coder *coder)). El flujo estricto debe ser este:

    Bloquear al Árbitro: El coder hace pthread_mutex_lock(&env->arbitrator_mutex).

    Apuntarse a la lista: El coder se añade a sí mismo al array queue.

        Si es FIFO: Se pone al final del array.

        Si es EDF: Se inserta en la posición correcta del array ordenando por quién tiene el deadline más cercano (su last_compile_start + time_to_burnout).

    El Bucle de Espera (El Filtro):
    Entra en un while que comprueba dos cosas:

        ¿Soy yo el primero en la cola? (env->queue[0] == coder->id)

        ¿Están mis dos dongles libres en heap_dongles?

        Si falla cualquiera de las dos: Llama a pthread_cond_wait(&env->cond_coders[coder->id], &env->arbitrator_mutex). Se va a dormir a su sala privada y suelta el candado del árbitro.

    El Éxito: Si sale del while, es porque es su turno y los dongles están libres.

        Marca sus dos casillas en heap_dongles como 1.

        Se borra a sí mismo de la queue (desplazando al resto de coders una posición hacia adelante).

    Desbloquear al Árbitro: Hace pthread_mutex_unlock(&env->arbitrator_mutex) y se va felizmente a compilar (usleep).

🔄 3. El Flujo de Ejecución: Cómo devolver los Dongles

Cuando termina el usleep de compilación, el coder debe devolver los recursos de forma inteligente para no provocar una estampida (Thundering Herd Problem).

    Bloquear al Árbitro: pthread_mutex_lock(&env->arbitrator_mutex).

    Soltar los recursos: Marca sus dos posiciones en heap_dongles como 0.

    El Despertador Quirúrgico:

        Mira quién es el siguiente en la lista de espera: next_id = env->queue[0].

        Comprueba si los dongles que necesita ese next_id están ahora libres.

        Si lo están, le manda un toque directo SOLO a ese coder: pthread_cond_signal(&env->cond_coders[next_id]).

    Desbloquear al Árbitro: pthread_mutex_unlock(&env->arbitrator_mutex).
